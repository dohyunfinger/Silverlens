# SilverLens

**'정의는 단순히 옳고 그름의 문제가 아니라 공동체의 선을 추구하는 행위, 자유와 평등에 더해서 우애 또는 연대성이라는 가치가 도입되어야 한다.'** 마이클 샌델이 말했습니다. 저희는 AI가 더 똑똑해지는 것보다, 사용자를 먼저 이해하고 사람간의 연대와 수치화 할수 없는 가치를 지켜주는 것이 진짜 발전된 기술이라고 생각합니다.
<br>**기술의 본질은 단순히 편리한 도구에 있는 것이 아니라, 인간과 세상을 연결하는 따뜻한 길이어야 한다고 생각합니다.**
SilverLens는 모든 것이 눈부시게 빨라지는 세상 속에서 소외된 어르신들의 삶을 돌아보고, 따뜻한 인공지능으로 세대 간의 단절을 메워나가는 시니어 맞춤형 AI 사이트입니다.

저희 팀은 처음에 '보이스피싱 예방 시스템'을 기획했습니다. 하지만 개발을 준비하면서 "이것이 과연 우리 할머니가 혼자 쓸 수 있는 다정한 기술인가?" 하는 근본적인 의문이 들었습니다. 노트북을 덮고 일주일 동안 가족들의 스마트폰 생활을 관찰하며, 우리는 책상 위에서는 보이지 않던 진짜 외로움과 장벽들을 발견했습니다.

**둔해진 손끝으로 작은 스마트폰 자판을 입력하는 어르신들에게 타이핑은 거대한 벽이었습니다.** 답답한 마음에 자판 대신 음성 인식을 켜보아도, 기존 AI들은 평생 삶의 흔적이 묻어난 깊은 사투리와 시장 언어(정구지, 정종 등)를 단지 '표준어가 아니다'라는 이유로 알아듣지 못하고 인식 오류만 냈습니다.

게다가 마트나 미디어에 쏟아지는 '로즈마리'나 '아보카도' 같은 낯선 외국 식재료들의 이름 앞에서 선뜻 손을 뻗지 못하고 망설이셨고, 인터넷에 떠도는 건강 정보를 무조건 신뢰하며 많이 먹을수록 좋다고 믿으시는 위험한 상황도 보았습니다.

> **기술의 속도가 노년의 걸음보다 빨라질 때, <br>어르신들은 기술을 거부하는 것이 아니라 기계 앞에서 서글픈 좌절감을 느끼고 계셨습니다. <br>현재의 기술은 어르신들이 기술을 못 쓰시는 게 아니라, 현재의 기술이 어르신들의 삶을 배려하지 않고 있었습니다.**

**사람을 소외시키는 기술은 결코 완성된 기술이 될 수 없습니다.** 저희 SilverLens는 어르신들이 기계의 규칙에 맞추는 것이 아니라, AI가 어르신의 삶을 먼저 이해하는 '눈과 귀'가 되고자 합니다. 디지털 격차를 해소하는 것을 넘어, 차가운 화면 속에서 따뜻한 사람의 온기를 전하는 사이트가 되는 것이 목표입니다.


# SilverLens의 핵심기술
**1. 사투리 찰떡 음성 인식**
<br>저희는 기술이 인간의 고유한 언어와 흔적을 존중해야 한다고 생각합니다. 
기존 AI는 표준어로 정확하게 발음하지 않으면 질문 자체를 거부합니다. SilverLens는 평생의 삶이 담긴 사투리와 생활 용어 데이터를 매핑하여, 어르신이 "이 정구지 어째 먹노?"라고 투박하게 말씀하셔도 그 안에 담긴 속뜻을 정확히 이해하고 손주처럼 다정하게 답변합니다. 

**2. 돋보기 카메라**
<br>지식의 나열보다 중요한 것은 한 사람을 향한 안전과 보호입니다.
기존 AI는 단순히 사진 속 사물의 이름만 딱딱한 데이터로 보여주고 끝냅니다. SilverLens는 카메라로 식재료를 비추면 낯선 외래어를 쉬운 우리말로 번역하고, 공공 영양 데이터와 연동하여 "할머니, 이 음식은 당뇨에 안 좋으니 조금만 드세요!" 하며 건강 맞춤형 안전 경고를 전달합니다. 

**3. 간단한 UI/UX와 손주 감성 음성**
<br>복잡한 메뉴와 카테고리는 어르신들에게 기술에 대한 두려움만 심어줄 뿐입니다. SilverLens는 어르신들의 인지 특성을 고려하여 복잡한 화면 구성을 직관적으로 단순화하고 글자 크기를 키웠습니다. 여기에 실제 손주의 목소리 톤을 학습한 TTS를 적용하여, 기계가 아닌 다정한 가족과 소통하는 듯한 정서적 안정감을 선물합니다.

# 디지털 세상의 소외를 지우는 빛, SilverLens
> **저희가 생각하는 가장 좋은 기술은 인간을 가르치려 들지 않고, 가장 낮은 곳에서 인간을 닮아가는 기술이라고 믿습니다.**

<br>**기술이 고도화될수록 소외받는 어르신들이 생겨난다면, 고등학생인 저희가 배운 기술로 그 격차를 가장 따뜻하게 메워보고 싶습니다.** 대한민국 모든 어르신들이 타인의 도움 없이도 당당하고 안전하게 디지털 세상을 누릴 수 있도록, 저희 SilverLens 팀은 기술에 마음을 담는 발걸음을 멈추지 않겠습니다.

# SilverLens 프로젝트 구조 및 아키텍처

## SilverLens란?

**SilverLens**는 시니어 사용자를 위한 **멀티모달 AI 식생활 도우미 서비스**입니다.

단순히 LLM(Gemini)에 질문을 전달하는 서비스가 아니라, **사용자의 질문과 프로필 정보를 바탕으로 관련 식생활·방언 DATA를 먼저 검색한 뒤, 그 검색 결과를 Gemini의 참고자료로 제공하여 최종 답변을 생성하는 구조**로 설계되었습니다.

즉, SilverLens의 핵심은 규칙 기반 답변 시스템이 아니라,

> **질문 + 사용자 프로필 + 검색된 도메인 DATA + 안전 프롬프트 + 멀티모달 입력을 기반으로 Gemini가 최종 응답을 생성하는 지식 보강형 생성 시스템**입니다.

프로젝트 전체는 **Next.js 기반 UI**, **API 계층**, **AI 처리 백엔드**, **도메인 DATA**, **Cloudflare 기반 서버리스 인프라**가 하나의 흐름으로 연결된 풀스택 AI 서비스입니다.

---

# 전체 시스템 아키텍처

```text
사용자 (텍스트 / 음성 / 사진)
           │
           ▼
Frontend
(SilverLensApp.tsx)
           │
           ▼
Next.js API
├── /api/chat
├── /api/transcribe
└── /api/tts
           │
           ▼
Backend
├── DATA 검색
├── Gemini 프롬프트 구성
├── Gemini 응답 생성
├── 음성 받아쓰기 및 건강정보 추출
└── TTS 생성
           │
           ▼
텍스트 응답 + 음성 응답
```

사용자 입력은 DATA가 직접 판정하는 것이 아니라, API와 Backend를 거치며 필요한 참고자료를 검색한 후 Gemini가 최종 답변을 생성합니다.

Cloudflare Workers와 Cloudflare D1은 현재 서비스의 서버리스 실행 환경과 확장성을 위한 인프라 계층이며, 현재 구현 기준에서는 핵심 질의응답 파이프라인보다 실행 환경을 지원하는 역할에 가깝습니다.

# 전체 처리 흐름

## 1. 사용자 입력

사용자는 다음 정보를 입력할 수 있습니다.

- 텍스트 질문
- 음성 질문
- 음식 사진
- 나이대
- 알레르기
- 질병
- 언어 선택

Frontend는 이 정보를 하나의 요청으로 묶어 서버 API에 전달합니다.

> Frontend는 Gemini를 직접 호출하지 않고 `/api/chat`, `/api/transcribe`, `/api/tts`를 호출합니다.

---

## 2. API 계층

### `/api/chat`

입력값을 먼저 검증합니다.

- 텍스트·음성·사진 중 하나 이상 존재하는지
- 질문 길이 제한
- 이미지 및 음성 데이터 크기 제한

검증이 완료되면 Backend AI 처리 로직을 호출합니다.

---

### `/api/transcribe`

음성 받아쓰기와 함께 건강정보를 구조화합니다.

```json
{
  "transcript": "...",
  "allergies": ["..."],
  "conditions": ["..."]
}
```

서버는

- 빈 값 제거
- 중복 제거
- 길이 제한

등의 후처리만 수행합니다.

> 질병과 알레르기 분류 역시 현재는 Gemini 기반 추론입니다.

---

### `/api/tts`

생성된 답변을 음성으로 변환합니다.

---

# Backend 계층

Backend는 SilverLens의 핵심 처리 엔진입니다.

주요 역할

- DATA 검색
- Gemini 프롬프트 구성
- Gemini 호출
- 음성 받아쓰기 후처리
- 건강정보 추출
- TTS 생성

```text
backend/
├── config/
├── data/
│   └── loadData.ts
├── services/
│   ├── geminiService.ts
│   ├── transcriptionService.ts
│   └── ttsService.ts
└── local_dialect/
    └── main.py
```

Backend는 단순 LLM 호출이 아니라, 사용자 입력과 내부 지식을 하나의 프롬프트로 구성하는 AI 처리 파이프라인입니다.

---

# DATA 검색 방식

현재 SilverLens는 **벡터 검색(RAG), 임베딩 검색, 시맨틱 검색을 사용하지 않습니다.**

검색은 **문자열 포함 여부와 점수 기반 검색**입니다.

검색 대상

- 사용자 질문
- 알레르기
- 질병

검색 결과

- 요리·재료 DATA 최대 4개
- 시니어 식품 DATA 최대 4개
- 방언 DATA 최대 20개

즉,

> **질문과 프로필을 기반으로 문자열·점수 방식으로 관련 DATA를 검색하는 경량 후보 검색기**입니다.

---

# Gemini 응답 생성

검색된 DATA는 Gemini 프롬프트에 포함됩니다.

프롬프트 구성 요소

- 질문
- 나이대
- 알레르기
- 질병
- 식품 DATA
- 요리·재료 DATA
- 방언 DATA
- 식품 별칭
- 안전 원칙
- 음성 입력
- 사진 입력

최종 구조

```text
최종 답변
=
Gemini(
    질문
    + 사용자 프로필
    + 검색된 DATA
    + 안전 프롬프트
    + 음성
    + 사진
)
```

> DATA는 참고자료이며, 최종 판단과 문장 생성은 Gemini가 수행합니다.

---

# TTS 처리

생성된 답변은 텍스트와 음성으로 함께 제공합니다.

```text
Gemini 답변
      │
      ▼
약 210자 단위 카드 분할
      │
      ▼
카드별 TTS 생성
      │
      ▼
브라우저 메모리 캐시
      │
      ▼
자동 순차 재생
```

동일한 답변을 다시 재생하면 캐시된 음성을 재사용하며, 새로고침 시 캐시는 초기화됩니다.

---

- 건강정보(JSON) 추출

을 수행합니다.

```json
{
  "transcript": "...",
  "allergies": ["..."],
```

# 현재 구현 기준에서 확인된 한계

현재 구현 설명 기준에서는 다음 사항을 함께 이해하는 것이 중요합니다.

- DATA는 AI가 학습한 것이 아니라 요청마다 검색되어 프롬프트에 포함되는 참고자료입니다.
- DATA 검색은 문자열·점수 기반이며, 임베딩 기반 검색은 확인되지 않았습니다.
- 최종 안전 판단은 규칙 엔진이 아니라 Gemini 생성 결과에 의존합니다.
- 별도의 의료 위험도 계산 엔진은 현재 구현 설명 기준에서는 확인되지 않았습니다.
- 사진 입력은 Gemini가 참고할 수 있지만, 사진 내용을 기반으로 DATA 검색이 완전히 연결된 것은 아닙니다.
- 질병·알레르기 분류는 현재 Gemini 추론을 기반으로 수행되며, 공식 의료 데이터베이스를 통한 재검증 로직은 확인되지 않았습니다.
- 성별은 현재 제공된 구현 기준에서는 AI 응답 생성에 사용되지 않습니다.
- 언어는 요청 데이터에는 포함되지만, 현재 제공된 구현 기준에서는 Gemini 답변 프롬프트에 직접 활용되지 않습니다.
- Cloudflare D1과 Drizzle ORM은 프로젝트에 포함되어 있지만, 현재 핵심 질의응답 파이프라인에서는 직접 사용되지 않습니다.

- 시니어 맞춤형 UI/UX

- 검색된 DATA를 Gemini 프롬프트 참고자료로 활용
- Gemini 기반 최종 응답 생성
